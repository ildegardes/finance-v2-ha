# Contrato SnapTrade Personal e diagnóstico da 0.1.37

A versão 0.1.36 consultava `GET /accounts/all` pelo método `list_all_user_accounts`, mas interpretava o resultado como uma lista direta e exigia `brokerage_authorization`, campo do modelo usado na rota anterior. O contrato da rota atual retorna um objeto com `results`. Cada conta identifica sua conexão com `connection_id`. Uma fixture conforme a OpenAPI reproduziu o erro `SNAPTRADE_INVALID_DATA` na versão publicada, mesmo com HTTP remoto 200 e assinatura Personal gerada pelo SDK. O payload da conta real ainda precisa ser homologado pelo proprietário. [List all user accounts](https://docs.snaptrade.com/reference/Account%20Information/AccountInformation_listAllUserAccounts) · [SDK Python 13.4.4](https://pypi.org/project/snaptrade-python-sdk/13.4.4/)

A descoberta aceita a lista documentada de conexões e valida os UUIDs e os vínculos antes de substituir o cache. A coleta de saldos, posições e atividades só roda para contas de investimento elegíveis. Nomes anuláveis recebem um rótulo local. Quando o estado de desativação da conexão está ausente ou nulo, a interface mostra estado desconhecido e a coleta dessa conexão fica suspensa. A apresentação de números de conta usa o sufixo fornecido de forma mascarada. [List all connections](https://docs.snaptrade.com/reference/Connections/Connections_listBrokerageAuthorizations)

O SDK assinou as cinco rotas de leitura em testes com transporte simulado. O teste observou o timeout de conexão e de leitura, os metadados de resposta e a ausência de `userId` e `userSecret`. A distinção entre recusa de assinatura e outras recusas de autenticação depende do sinal documentado pelo provedor. A aplicação descarta textos e cabeçalhos externos ao registrar falhas. [Personal API Key](https://docs.snaptrade.com/docs/personal-api-key) · [Erros de assinatura](https://docs.snaptrade.com/docs/faq)

A resposta de falha, o status autenticado e o log compartilham um identificador gerado pelo Finance. O registro durável reaproveita `st_events` do schema 16. Inclui a data, operação, resultado, etapa, recurso lógico, motivo e, quando aplicável, nome fixo do campo e status HTTP remoto. Os erros do provedor continuam com HTTP 502 para falhas completas, 429 para limite global e 503 para falha de persistência. A interface consulta o status após a operação, inclusive quando o proxy devolve HTML em vez do JSON do Finance. [HTTP 502 e 504](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-502-504/)
